First, who is Jason?

Who is Jason?

Not a person. JSON is a simple text format for data, the shape a message travels in between programs.

What is an API?

A doorway one program uses to ask another for something. Like a waiter: you order, it fetches, you never enter the kitchen.

What's on the wire?

HTTP: the request going out and the response coming back. One side asks, the other answers, and that's the whole exchange.

How smart is an AI?

Not smart the way people are. An LLM doesn't know things, it just predicts the next word extremely well.

Why do I need a key?

The API key proves who you are, like a name on the guest list. It's how the server knows you're allowed in and who to bill.

Who is asking whom?

Your laptop is the client, the one that asks. A bigger computer elsewhere is the server, the one that answers.

Session 2 / 5
Say My Name
Give the model memory, so it feels like it remembers you.

Concepts so far

Context

The whole conversation history you send the model on every request. It's what the model "sees" when it writes a reply.

Memory

How we fake remembering. The model keeps no state of its own, so we just resend the history each time.

Tokens

The unit the model thinks in, and the unit it charges by. A longer conversation costs more on every turn.

RAG

Rather than stuff everything in upfront, you fetch only the relevant pieces at the moment you ask.

Compaction

What you do when the history gets too long: summarise or drop the oldest messages so it still fits.

Context Window

The hard limit on how many tokens a model can receive at once.

Session 3 / 5
Say My Name, Literally
Shape behaviour with a system prompt and structured output.

Concepts so far

System Prompt

A hidden instruction that rides along on every request and shapes how the model behaves. The user never sees it; the model always obeys it.

Structured Output

Forcing the model to answer in a fixed shape (say, JSON) so your code can parse it and act on it without guessing.

Determinism

LLMs are probabilistic by default, so the same input can give different output. Structure and careful prompting make them steadier, though never fully predictable.

Prompt Engineering

The practice of crafting instructions to get reliable, useful outputs.

Output Parsing

The other half of structured output. Your code reads the model's reply and pulls out enough meaning to act on it.

Grounding

Tying the model's answer to real facts or rules instead of letting it wander. A system prompt is one way to ground it.

Session 4 / 5
Say My Name, Automatically
Give it tools. Now the model decides what to do.

Concepts so far

Tools

Capabilities you hand the model by declaring them upfront. It decides when to call one; your code runs it.

MCP

A standard for defining and connecting tools across different models and hosts.

Function Calling

The API mechanism where the model emits a structured request to call a tool. Tools are the idea; this is the wire format that carries it.

Human in the Loop

A checkpoint where a human reviews or approves before the agent proceeds.

Context Bloat

Every tool call and its result gets added to the history, so the context grows fast and each round trip eats into your window.

Agentic Behaviour

The moment the model starts deciding what to do, rather than just responding.

Session 5 / 5
Make sure you say my name
The loop, multiple agents, and guardrails.

Concepts so far

Agentic Loop

The think, act, observe cycle that every agent runs on. The model calls a tool, reads the result, and decides the next move until the job is done.

Multiagent Systems

Several agents working together, each with its own tools and instructions. One agent can drive the others as if they were tools.

Orchestration

The logic that picks which agent or tool goes next, in what order, and what to do when one of them fails.

Autonomous Execution

The model runs a whole sequence of actions on its own, without a human signing off on each step.

Guardrails

Limits on what an autonomous agent is allowed to do or say. The more freedom you give the model, the more they matter.

Tool Result

The response your code sends back after executing a tool. The model uses it to decide what to do next.
